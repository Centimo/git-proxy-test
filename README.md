# git-proxy

Локальный git-зеркальный прокси на базе Forgejo для кеширования внешних репозиториев.

## Цель

Ускорить и надёжнее сделать CI-сборки, которым нужно клонировать репозитории с GitHub.
В частности — для получения корректного RREV в `conan graph build-order` + lockfile подходе,
где нужно клонировать репозитории с `export_sources()` (protobuf, Simd).

## Желаемое поведение

Если из локальной сети приходит `git clone github.com/Centimo/protobuf`:
1. Прокси перехватывает запрос
2. Проверяет — есть ли уже зеркало в Forgejo
3. Если нет — создаёт pull mirror через Forgejo API, возвращает ошибку клиенту (retry)
4. Если есть — проксирует запрос в Forgejo, клиент получает локальную копию

Forgejo периодически синхронизирует зеркала с GitHub.

## Компоненты

- **Forgejo** — git-сервер, хранит зеркала репозиториев
- **git-proxy** — HTTP-прокси перед Forgejo, реализует автосоздание mirror по запросу

## Открытые вопросы

- [x] Поведение Forgejo при `git clone` в момент initial sync:
  возвращает пустой репо, блокирует соединение или ошибку?
  **Результат эксперимента (2026-04-11):** Forgejo возвращает **пустой репозиторий** — `git clone`
  завершается успешно с `warning: You appear to have cloned an empty repository`.
  Никакой ошибки, никакой блокировки.

  Дополнительно выяснено: `/api/v1/repos/migrate` ведёт себя по-разному в зависимости от размера:
  - Малые репо (~секунды клонирования): синхронный — 201 возвращается только после полного клона.
  - Большие репо: возвращает 201 до завершения клонирования; в момент ответа `empty: true, size: 0`.

  **Вывод для git-proxy:** недостаточно проверять факт существования репо — нужно проверять
  флаг `empty`. Если `empty: true` — mirror ещё не готов, нужно вернуть клиенту ошибку (retry).

## План

1. Развернуть Forgejo локально (Docker)
2. Проверить поведение при clone во время initial sync
3. Написать git-proxy (Python/aiohttp или Go)
4. Интегрировать в CI: заменить `github.com` на адрес прокси в `packages.yml`

## Выбор: Forgejo vs Gitea

Выбран **Forgejo**:
- Fork Gitea, MIT + GPL лицензия, бесплатно для коммерческого использования
- Более активное community-driven развитие
- Gitea сместилась в сторону коммерциализации (Gitea Ltd)
- Функционально идентичны для нашей задачи
